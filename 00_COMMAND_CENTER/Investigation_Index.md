## Case Identification Standard

Use the following identifier format:

`ARGUS-YYYY-NNN`

Examples:

- `ARGUS-2026-001`
- `ARGUS-2026-002`
- `ARGUS-2027-001`

## Investigation Directory Structure

Each authorized investigation should have its own structured workspace.

- Case Overview
- Objectives and Scope
- Sources
- Entities
- Evidence Metadata
- Timeline
- Analysis
- Findings
- Final Report

## Operational Rules

1. Assign a unique identifier to every investigation.
2. Define the scope and authorization before collection.
3. Record the origin and collection date of every source.
4. Distinguish verified facts from hypotheses.
5. Maintain evidence integrity and traceability.
6. Restrict access to confidential investigation data.
7. Document conclusions and methodological limitations.

## Important Notice

This index is intended for case references and non-sensitive metadata.

Original evidence, personal information, credentials and confidential investigation records must remain in protected storage outside the Git repository.
